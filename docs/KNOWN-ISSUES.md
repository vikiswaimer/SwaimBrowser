# Известные ограничения и технический долг

Документ описывает текущие ограничения, осознанные решения "не делаем", известные проблемы и планы по их устранению.

> **Скоуп v0.1:** см. [PRD.md](./PRD.md) — что делаем и что НЕ делаем  
> **Терминология:** см. [GLOSSARY.md](./GLOSSARY.md)  
> **Цель документа:** предотвратить повторные предложения решений, которые уже были рассмотрены и отклонены или отложены.

## Ограничения Electron

### Архитектурные ограничения

| Ограничение | Описание | Влияние |
|-------------|----------|---------|
| **Размер приложения** | Electron включает Chromium (~150-200 MB минимум) | Большой размер дистрибутива, долгая загрузка |
| **Память** | Chromium потребляет значительный объём RAM | Высокое потребление памяти (300+ MB базово) |
| **Холодный старт** | Запуск Chromium занимает время | 2-5 секунд до готовности приложения |

### Платформенные ограничения

| Платформа | Ограничение |
|-----------|-------------|
| **macOS ARM (Apple Silicon)** | Требуется отдельная сборка для ARM или universal binary |
| **Linux** | Зависимости от системных библиотек (GTK, libnss3, libatk и др.) |
| **Windows** | Нет нативной поддержки Windows on ARM |

### Текущая реализация

- **Webview** — используется `<webview>` тег с отключенным `nodeIntegration` и включенным `contextIsolation` для безопасности
- **Preload scripts** — используются для безопасного взаимодействия между renderer и main процессами
- **IPC** — вся коммуникация между процессами через `ipcMain` / `ipcRenderer`

## Осознанные решения "не делаем"

Следующие функции были рассмотрены и сознательно отложены или исключены:

| Функция | Причина | Пересмотреть когда |
|---------|---------|-------------------|
| **Автообновления** | Сложность реализации, проблемы с code signing | Стабильная user base (1000+ пользователей) |
| **Mobile/Web версия** | Electron — desktop технология; фокус на desktop | Валидация PMF на desktop |
| **Облачная синхронизация** | Приватность, отсутствие backend | Потребность в team features |
| **Multi-profile** | Усложнение UX, низкий приоритет для MVP | Запрос от пользователей |
| **Chrome Extensions** | Сложность интеграции в текущей архитектуре | После стабилизации MVP |

## Ограничения UX

### 1. Prompt для ввода инсайта

**Проблема:** Используется `prompt()`, который:
- Блокирует весь UI
- Не поддерживает многострочный текст
- Не позволяет отменить без потери данных

**Где:** `src/App.tsx`, обработчик горячих клавиш

**Влияние:** Плохой UX при частом сохранении инсайтов.

**План:** Заменить на inline-форму или floating widget.

---

### 2. Показываются только 5 последних инсайтов

**Проблема:** Ограничение на количество отображаемых инсайтов.

**Где:** `src/store/insightsStore.ts`

**Влияние:** Нет доступа к старым инсайтам через UI.

**План:** Добавить пагинацию или infinite scroll.

---

### 3. Теги инсайтов не используются

**Проблема:** Поле `tags: []` всегда пустое, UI для тегов отсутствует.

**Где:** Формат инсайта в `src/shared/types.ts`

**Влияние:** Невозможно категоризировать инсайты.

**План:** Добавить UI для тегов или автоматическую классификацию.

---

## Технический долг

### 4. Focus таймер без восстановления при перезагрузке

**Проблема:** При перезагрузке страницы таймер сбрасывается.

**Где:** `src/store/focusStore.ts`

**Влияние:** Потеря прогресса сессии при случайной перезагрузке.

**План:** Сохранять состояние таймера в electron-store.

---

### 5. Нет валидации URL

**Проблема:** URL вводится без полной валидации.

**Где:** `src/components/TopBar/TopBar.tsx`

**Влияние:** Возможны ошибки навигации.

**План:** Добавить proper URL validation и sanitization.
